# MagicBox Engineering Principles

## Maintainability

- One role per concern: `preflight`, `mdns`, `firewall`, `docker`,
  `portainer`. A role owns its packages, files, services and verification.
- Explicit over clever: settings are visible in `defaults/main.yml` with a
  comment explaining why they exist. No hidden behaviour in templates.
- Pin everything that can drift (ADR-0001, ADR-0002) and upgrade deliberately.
- Prefer deleting configuration to adding toggles. A variable exists only if a
  real environment needs a different value.

## Clean Code

- Ansible: fully qualified module names, `name:` on every task in imperative
  form, role variables prefixed with the role name, shared settings prefixed
  `magicbox_`, `ansible.builtin.command` only with `argv` and
  `changed_when`. Lint with the ansible-lint `production` profile.
- YAML: 2-space indent, explicit `true`/`false`, quoted file modes
  (`"0644"`).
- Python tools: standard library first, type hints, a module docstring with
  usage, non-zero exit on failure, no network access unless that is the
  tool's purpose.
- Comments explain *why*, not what the next line does.

## Pragmatic Clean Architecture

- Layers: inventory (environment facts) -> group vars (project policy) -> role
  defaults (mechanism defaults) -> roles (mechanism). Roles never contain
  environment-specific values.
- Dependencies point inwards: `portainer` depends on Docker being installed,
  not on how; `firewall` depends only on `magicbox_lan_cidr`.
- No abstraction without a second use case. Single host, single playbook.

## Security-First Practices

- Least exposure: default-deny firewall, LAN-only management, no plain HTTP,
  no Docker TCP API, Avahi bound to the LAN interface, no HINFO publishing.
- Secrets: only in ansible-vault (`inventory/group_vars/magicbox/vault.yml`,
  git-ignored), referenced through `vault_*` variables, `no_log: true` on tasks
  that handle them. `tools/check_secrets.py` blocks plaintext secrets and
  private keys in tracked files.
- Supply chain: verify the Docker apt key fingerprint before trusting it; pin
  image tags and collection versions; take dependencies only from official
  sources.
- Privilege awareness: the Docker socket is root-equivalent (ADR-0006). Do not
  add users to the `docker` group; treat Portainer admins as root.
- Safety rails: destructive steps require `magicbox_confirm_destructive=true`
  (ADR-0008); the playbook refuses to enable the firewall from outside the LAN.
- Never invent environment details or credentials; fail with a clear message
  when they are missing.

## Testing

- Every change: `make check` (syntax, yamllint, ansible-lint, secrets, manuals,
  documentation consistency).
- Role changes: `make test-container` (converge + idempotency in a systemd
  container, ADR-0009).
- On MagicBox: `make deploy`, then `make idempotency` and `make verify`. Roles
  contain `verify`-tagged assertions that check behaviour (name resolution,
  listeners, HTTPS with CA validation), not just task success.
- Report results honestly: distinguish "verified on MagicBox", "verified in
  the test container" and "not executed".

## Documentation Standards

- English only. Markdown for sources; PDFs generated by
  `tools/build_manuals.py` and committed.
- `CLAUDE.md` links every document, manual, ADR and tool;
  `tools/check_docs.py` fails when a link is missing or broken.
- `manuals/src/magicbox-playbook.md` documents every role, variable and tag
  (enforced) and is updated in the same change as the code.
- ADRs record significant decisions with Status, Context, Decision,
  Alternatives and Consequences (enforced).
- No placeholders: instructions must be concrete commands or explicit owner
  inputs (marked `CHANGE_ME` in examples only).
