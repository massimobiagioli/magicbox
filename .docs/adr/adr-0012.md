# ADR-0012: Restrict Docker-published ports to the LAN with DOCKER-USER

- **Date:** 2026-10-28
- **Deciders:** MagicBox maintainers

## Status

Accepted. Resolves the published-port risk recorded in ADR-0004.

## Context

The default stacks (ADR-0011) publish ports on Docker bridge networks.
Docker's DNAT rules send that traffic through the `FORWARD` chain, so ufw's
`INPUT` rules never see it: without extra rules, a port forwarded by the router
would expose PostgreSQL or Ollama to the internet. Docker evaluates the
`DOCKER-USER` chain before its own forwarding rules and never flushes it.

## Decision

- The `firewall` role adds a block to `/etc/ufw/after.rules` (enabled by
  `firewall_docker_user_filter`, default `true`):

```text
*filter
:DOCKER-USER - [0:0]
-A DOCKER-USER -m conntrack --ctstate RELATED,ESTABLISHED -j RETURN
-A DOCKER-USER -i <lan interface> -s <magicbox_lan_cidr> -j RETURN
-A DOCKER-USER -i <lan interface> -j DROP
-A DOCKER-USER -j RETURN
COMMIT
```

- ufw loads it on every start and reload. It replaces the chain each time,
  which keeps it idempotent, and it exists before Docker starts.
- A `verify` task asserts the chain contains the LAN rule and the DROP rule.

## Alternatives

- **Bind published ports to the LAN IP:** the IP is dynamic (ADR-0003);
  rejected.
- **Host networking for every stack:** loses network isolation between
  services; rejected.
- **ufw-docker helper script:** same mechanism, extra unpinned dependency;
  rejected.

## Consequences

- All Docker-published ports are reachable from `magicbox_lan_cidr` only,
  whatever the stack definition says. Replies to container-initiated
  connections still work.
- IPv6 published ports are not covered; Docker IPv6 stays disabled (default).
