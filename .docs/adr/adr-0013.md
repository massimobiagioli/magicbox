# ADR-0013: Log collection with Grafana Alloy instead of Promtail

- **Date:** 2026-10-28
- **Deciders:** MagicBox maintainers

## Status

Accepted

## Context

The owner asked for Grafana with Loki and Promtail. Grafana's documentation
states: "Promtail is end of life (EOL) as of March 2, 2026. Commercial support
has ended. No future support or updates will be provided." The last Promtail
image is 3.6.11 (2026-05-13). Grafana Alloy is the official successor.
Collecting Docker logs with container names usually means mounting the Docker
socket, which is root-equivalent (ADR-0006).

## Decision

- Use **Grafana Alloy** (`grafana/alloy:v1.21.2`) as the collector in the
  `observability` stack, in Promtail's place.
- Alloy reads Docker json-file logs from `/var/lib/docker/containers`
  (read-only). The `docker` role sets the log option `tag` to the container
  name (`{{.Name}}`), so each line carries it and Alloy turns it into the
  `container` label. **No Docker socket is mounted.**
- Alloy also reads the host systemd journal (`/var/log/journal`, read-only;
  labels `job=journal`, `unit`, `level`), which works on Ubuntu and Debian
  with or without rsyslog.
- Loki runs as a single binary with filesystem storage, TSDB schema v13 and
  retention `stacks_loki_retention` (default 7 days). Grafana gets Loki as a
  provisioned, read-only default data source.

## Alternatives

- **Promtail 3.6.11 as requested:** end of life, so no security fixes;
  rejected.
- **Alloy with `loki.source.docker` and the Docker socket:** richer metadata,
  but gives the collector root-equivalent access; rejected.

## Consequences

- The stack is called "Grafana + Loki + Alloy"; Alloy fills the role
  Promtail had.
- Containers created before the `tag` log option was set (Portainer itself
  after an upgrade from an older MagicBox install) get no `container` label
  until they are recreated.
- Alloy runs as root inside its container to read root-owned log files
  (read-only mounts).
