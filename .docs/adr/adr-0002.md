# ADR-0002: Supported target OS and Docker Engine source

- **Date:** 2026-10-28
- **Deciders:** MagicBox maintainers

## Status

Accepted. The concrete OS installed on MagicBox is still to be confirmed by the
owner (see the installation manual, "Manual Steps").

## Context

The playbook must not guess the operating system. Docker Engine packages,
Avahi, ufw and systemd behave consistently on current Debian-family releases.
Docker publishes official packages for Ubuntu 24.04 (noble), 26.04 (resolute),
Debian 12 (bookworm) and 13 (trixie); on 2026-10-28 all of them carried
`docker-ce 5:29.9.2`. Distribution `docker.io` packages lag behind and conflict
with Docker CE.

## Decision

- Supported targets: Ubuntu Server 24.04/26.04 LTS and Debian 12/13 on
  `x86_64`. The `preflight` role asserts OS, version and architecture and stops
  otherwise. Ubuntu Server 24.04 LTS is the recommended install.
- Docker Engine comes from `download.docker.com` with the signing key verified
  against fingerprint `9DC858229FC7DD38854AE2D88D81803C0EBFCD88` before it is
  trusted, configured as a deb822 source.
- An apt preference pins `docker-ce`, `docker-ce-cli` and
  `docker-ce-rootless-extras` to major version 29 (`docker_major_version`).
  Patch releases within the major are allowed.
- Conflicting distribution packages are removed only with explicit
  confirmation (ADR-0008).

## Alternatives

- **Distribution `docker.io`:** older, different upgrade cadence; rejected.
- **Exact apt version pin:** fully reproducible but breaks as soon as the
  repository rotates old patch versions and blocks security fixes; rejected in
  favour of a major-version pin.
- **Docker convenience script (`get.docker.com`):** unpinned, non-idempotent;
  rejected.
- **Podman:** Portainer's primary target is Docker; rejected.

## Consequences

- Moving to Docker 30 is a deliberate change of `docker_major_version` plus a
  test run.
- Unsupported OS versions fail fast with a clear message instead of
  half-configuring the host.
