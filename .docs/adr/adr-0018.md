# ADR-0018: RustFS object storage with the console on its own port

- **Date:** 2026-10-30
- **Deciders:** MagicBox maintainers

## Status

Accepted

## Context

Apps on MagicBox need simple S3-compatible bucket storage. MinIO is excluded
by the owner. Candidates: Garage (light, no built-in UI), SeaweedFS (several
components), Versity S3 Gateway, Zenko CloudServer, Ceph RGW (too heavy).
RustFS (Apache-2.0, Rust, single container, about 80 MB of RAM idle) offers a
broad S3 API and a web console similar to MinIO's.

The API gateway routes by path (ADR-0015), which does not fit RustFS:

- S3 clients sign the request path (SigV4), so the S3 API must be served from
  the root of its host and port, not under a stripped gateway prefix.
- The console (served under `/rustfs/console/`) sends its S3 and admin calls
  to the origin of the page. Behind `https://magicbox.local/rustfs/` those
  calls would reach `https://magicbox.local/<bucket>`, which Kong does not
  route. Verified on `rustfs/rustfs:1.0.4`: the console port also answers the
  S3 and admin APIs, so the console works when opened on its own port.

## Decision

- RustFS is the Portainer stack `rustfs`, deployed by its own playbook
  (`playbooks/storage.yml`, `make storage`), image pinned
  (`stacks_rustfs_image`), one data volume `rustfs_data` (single drive, no
  erasure-coding parity).
- Both ports serve HTTPS with a copy of the MagicBox certificate
  (`RUSTFS_TLS_PATH`): S3 API on `stacks_rustfs_api_port` (9100), console on
  `stacks_rustfs_console_port` (9101). Not the upstream 9000/9001: port 9000
  must stay closed (CONSTITUTION, Portainer legacy HTTP). Both are published
  and limited to the LAN by DOCKER-USER (ADR-0012).
- Root credentials from the vault (`vault_rustfs_access_key`,
  `vault_rustfs_secret_key`), applied at every start.
- Gateway: `https://magicbox.local/rustfs` is a 301 redirect to the console
  on its own port (`stacks_kong_port_redirects`), not a proxied route.
- Logs go to stdout (collected by Alloy).

## Alternatives

- **Proxy the console under `/rustfs/`:** login works, bucket browsing does
  not (calls go to the gateway root); rejected.
- **Separate host names (`s3.magicbox.local`, `console.magicbox.local`):**
  multi-label mDNS names resolve unreliably on Windows and Android and need a
  new certificate; rejected.
- **Garage:** lighter and mature, but no built-in UI; kept as the fallback if
  RustFS proves unstable.
- **Plain HTTP on the ports:** simpler, but credentials and data would cross
  the LAN in clear; rejected.

## Consequences

- RustFS is reached on its own ports (9100 S3, 9101 console); the gateway
  path is only a shortcut. This is the documented exception to "every UI
  through the gateway".
- After a certificate renewal by `site.yml`, run `make storage` to refresh
  RustFS's copy.
- Single drive: no redundancy; back up `rustfs_data` like the other volumes.
- RustFS is a young project: pin its version and read release notes before
  upgrading.
