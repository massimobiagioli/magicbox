# ADR-0003: Name resolution for magicbox.local via Avahi mDNS

- **Date:** 2026-10-28
- **Deciders:** MagicBox maintainers

## Status

Accepted

## Context

LAN clients must reach `https://magicbox.local:9443/`. The `.local` top-level
domain is reserved for Multicast DNS (RFC 6762); unicast DNS servers should not
answer it and many clients send `.local` queries only via mDNS. Client support:
macOS and iOS resolve mDNS natively; Windows 10 (1803+) and 11 resolve `.local`
via their built-in mDNS client; Linux desktops need `nss-mdns`/Avahi (or
systemd-resolved with mDNS enabled); Android resolves `.local` on 12+ in most
apps. mDNS does not cross routers or VLANs and is often blocked on guest Wi-Fi
with client isolation. On Ubuntu, systemd-resolved can also bind UDP 5353.

## Decision

- Avahi (`avahi-daemon`) is the only mDNS responder on MagicBox. It publishes
  `magicbox.local` (A and, by default, AAAA records) only on
  `magicbox_lan_interface`, with HINFO and workstation records disabled.
- A systemd-resolved drop-in sets `MulticastDNS=no` and `LLMNR=no` so two
  responders never compete for port 5353.
- The OS hostname is set to `magicbox` so Avahi does not need to rename on
  conflicts and logs/shell prompts match.
- `libnss-mdns` is installed on MagicBox so the host resolves its own name;
  the playbook verifies `avahi-resolve-host-name -4 magicbox.local`.
- The router should give MagicBox a DHCP reservation. This is a manual step
  because router access is outside the playbook.
- Fallbacks for clients without mDNS are documented, not automated: a hosts
  file entry, or a router DNS override for `magicbox.local`.

## Alternatives

- **Unicast DNS name (e.g. `magicbox.home.arpa`):** most reliable, but needs
  control of the LAN DNS server and does not satisfy the required URL; can be
  added later as an extra TLS SAN.
- **systemd-resolved as mDNS responder:** fewer packages, but Avahi has broader
  tooling (`avahi-resolve`, `avahi-browse`) and is the Debian/Ubuntu default
  responder; rejected.
- **Static IP configured by the playbook:** would require inventing gateway
  and DNS settings; rejected in favour of a DHCP reservation.

## Consequences

- Clients on another subnet/VLAN cannot resolve `magicbox.local` unless the
  network runs an mDNS reflector; use the IP or a DNS override there.
- Two devices named `magicbox` on the same LAN would collide; Avahi would
  rename one (`magicbox-2.local`), which breaks the TLS name match. The
  verification task detects this.
