# ADR-0009: Project tools in tools/ and container-based convergence tests

- **Date:** 2026-10-28
- **Deciders:** MagicBox maintainers

## Status

Accepted

## Context

The project needs helper programs (PDF build, documentation checks, secret
checks, idempotency checks). Ad-hoc one-off commands are not reviewable or
repeatable. The real MagicBox is not always reachable from the maintainer's
workstation, yet roles must be exercised before they touch the host.

## Decision

- Every helper is a script in `tools/`, run with `uv run tools/<name>`, with a
  usage docstring, and listed in `CLAUDE.md`. New needs (for example a format
  converter) are met by adding a tool there instead of running unrecorded
  commands. Tools use only dependencies pinned in `pyproject.toml`.
- `tools/container_test.py` runs the full playbook twice against a disposable
  privileged systemd container (`tests/container/`), using
  `tools/idempotency_check.py` to require `changed=0` on the second run.
  Container-only differences are expressed as host vars in
  `tests/container/hosts.yml` (architecture, LAN interface,
  `preflight_manage_hostname: false`).

## Alternatives

- **Molecule:** standard, but adds drivers and scenario layout for a single
  host; may be adopted later if roles multiply.
- **Vagrant/VM tests:** closer to real hardware but slow and not available on
  every workstation; rejected for now.

## Consequences

- `make test-container` gives a real converge + idempotency signal locally.
- The container is not MagicBox: it does not prove LAN mDNS, real firewall
  reachability from other machines, or x86_64 package availability. Those are
  verified on the host with `make verify` and the manual checks.
