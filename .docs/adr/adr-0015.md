# ADR-0015: Kong API gateway with path-based routes

- **Date:** 2026-10-29
- **Deciders:** MagicBox maintainers

## Status

Accepted

## Context

Each MagicBox service has its own port (Portainer 9443, Jenkins 8443, Grafana
3000, RabbitMQ 15672, Ollama 11434). The owner wants a single entry point,
`https://magicbox.local/<service>`, managed by Kong. MagicBox has one mDNS name
and the local CA is name-constrained to `magicbox.local` and `magicbox`
(ADR-0003, ADR-0005), so host-based routing (`jenkins.magicbox.local`) is not
available: routes must be paths. Ollama has no authentication and no UI.

Kong Gateway's open-source line ends at 3.9 (`kong:3.9.x` on Docker Hub);
later releases are the enterprise image `kong/kong-gateway`.

## Decision

- Deploy Kong OSS (`kong:3.9.4`) in DB-less mode as the Portainer stack
  `kong` with `playbooks/api-gateway.yml` (`make api-gateway`), reusing the
  `stacks` role. The declarative configuration is rendered by Ansible
  (`roles/stacks/templates/kong/kong.yaml.j2`); a change redeploys Kong.
- Host networking, like Portainer (ADR-0004): Kong listens on 80 (301 to
  HTTPS only) and 443 with the MagicBox certificate; the firewall role allows
  both from `magicbox_lan_cidr`. Upstreams are reached on `127.0.0.1`, so
  Kong does not depend on the stacks' Docker networks, and an absent service
  (e.g. Jenkins not installed) only makes its route return 502. Kong's nginx
  master runs as root to bind 80/443; workers run as `kong`.
- Admin API and status endpoint on loopback only; Kong Manager disabled.
- Routes: `/portainer/`, `/ollama/` (path stripped), `/jenkins`, `/grafana`,
  `/rabbitmq` (not stripped: these services are configured to serve from the
  same sub-path on their own port too, so links work both ways). `/` and
  `/portainer` redirect to `/portainer/`.
- `/ollama/` requires a Kong `key-auth` API key (`vault_kong_ollama_api_key`,
  header or query parameter `apikey`), not forwarded to Ollama.
- Upstream TLS certificates are not verified: the traffic never leaves the
  host, and the certificates name `magicbox.local`, not `127.0.0.1`.

## Alternatives

- **Traefik, Caddy or nginx:** simpler for a pure reverse proxy; rejected
  because the owner asked for Kong (API keys and plugins available later).
- **Kong in bridge networking with published ports:** cross-network traffic
  to published ports and Portainer (host network) would need extra ufw and
  Docker isolation exceptions.
- **Kong with PostgreSQL (DB mode) and Kong Manager:** UI-driven changes
  would drift from the Ansible-rendered configuration.
- **Host-based routing:** needs more mDNS names and a new CA.

## Consequences

- Jenkins, Grafana and the RabbitMQ management UI move to `/jenkins/`,
  `/grafana/` and `/rabbitmq/` on their own ports as well; old root URLs and
  bookmarks stop working. Portainer and Ollama keep their root paths.
- The direct ports stay open on the LAN. In particular Ollama on 11434 is
  still unauthenticated; the API key only protects the gateway route.
- Kong reads its own copy of the MagicBox certificate: after a renewal by
  `site.yml`, run `make api-gateway` to refresh it.
- The API key is stored in the vault and, in plain text, in
  `/opt/magicbox/stacks/kong/declarative/kong.yaml` (root, mode 0400).
