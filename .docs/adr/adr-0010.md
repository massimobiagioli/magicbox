# ADR-0010: Portainer initialisation and the "homelab" site environment

- **Date:** 2026-10-28
- **Deciders:** MagicBox maintainers

## Status

Accepted

## Context

After first start, Portainer 2.45.3 has an admin user (ADR-0006) but **no
environment**: verified on 2026-10-28, `GET /api/endpoints` returns `[]` until
someone completes the UI wizard. Stacks can only be deployed into an
environment, and the owner wants that environment (the "site") to be named
`homelab`, configurable.

## Decision

- A `portainer_init` role (in `playbooks/site.yml`, after `portainer`) logs in
  to the Portainer API as `admin` with the vault password and ensures exactly
  one local Docker environment named `magicbox_site_name` (default `homelab`,
  in `inventory/group_vars/magicbox/main.yml`):
  - if it exists, nothing changes;
  - if a local-socket environment exists under another name (for example
    `local` created through the wizard), it is renamed;
  - otherwise it is created (`POST /api/endpoints`, `EndpointCreationType=1`,
    `unix:///var/run/docker.sock`).
- API calls run on MagicBox against `https://magicbox.local:9443` and validate
  the certificate with the MagicBox CA.
- The login tasks (`api_login.yml`) are shared with the `stacks` role.

## Alternatives

- **Portainer `-H unix:///var/run/docker.sock` flag:** creates an environment
  named `primary` at startup; the name is not configurable; rejected.
- **Environment groups or tags named "homelab":** a Portainer environment is
  what stacks target; groups can be added later if more environments appear.
- **Manual wizard:** not reproducible; rejected.

## Consequences

- `site.yml` leaves Portainer ready for stacks without opening the UI.
- If the admin password is changed in the UI, `vault_portainer_admin_password`
  must be updated too, or `portainer_init` and `stacks` fail at login with a
  clear message.
- Renaming the site later (changing `magicbox_site_name`) creates a new
  environment unless the old one is renamed in the UI first.
