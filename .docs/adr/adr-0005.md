# ADR-0005: HTTPS with a name-constrained local CA generated on MagicBox

- **Date:** 2026-10-28
- **Deciders:** MagicBox maintainers

## Status

Accepted

## Context

Public CAs cannot issue certificates for `.local` names, so a browser-trusted
certificate for `magicbox.local` must come from a private CA that LAN clients
explicitly trust. Portainer's built-in self-signed certificate changes on
reinstall and offers no trust anchor to distribute. A private root installed in
client trust stores is powerful: if its key leaks it could impersonate any
website to those clients.

## Decision

- Default `portainer_tls_mode: local_ca`. The `portainer` role, using
  `community.crypto`, creates on MagicBox:
  - `ca.key` (ECDSA P-384, mode 0600) and `ca.crt` (10 years, `CA:TRUE,
    pathlen:0`, critical **name constraints** permitting only the names in
    `portainer_tls_dns_names` and any `portainer_tls_ip_addresses`);
  - `portainer.key` (ECDSA P-256, mode 0600) and `portainer.crt` (397 days,
    SANs `magicbox.local` and `magicbox`, EKU `serverAuth`).
- The server certificate is re-issued automatically when it would expire
  within `portainer_tls_renew_before` (30 days); Portainer restarts via a
  handler.
- `ca.crt` is fetched to `artifacts/magicbox-local-ca.crt` on the controller
  (git-ignored) for installation on LAN clients; the installation manual
  covers macOS, Windows, Linux, Firefox, iOS and Android.
- `portainer_tls_mode: provided` installs an existing certificate, key and CA
  from controller paths for owners who already run a private PKI.

## Alternatives

- **Portainer's default self-signed certificate:** permanent browser warnings
  train users to click through; rejected.
- **mkcert on the controller:** good UX, but its root CA is not name-constrained
  and lives on a workstation; rejected as the default.
- **ACME/Let's Encrypt with a real domain:** needs a public domain and DNS
  challenge and does not cover `.local`; possible later with an extra name.
- **Generate the CA on the controller:** survives a MagicBox rebuild, but puts
  the CA key on a laptop; rejected for the default. Use `provided` mode if this
  is preferred.

## Consequences

- Every LAN client must trust the CA once; until then browsers warn.
- Rebuilding MagicBox from scratch generates a new CA; clients must trust the
  new `ca.crt`. Back up `/opt/magicbox/portainer/certs/` to avoid this.
- Name constraints limit damage from a leaked CA key to MagicBox names.
- Leaf validity of 397 days stays within browser limits for TLS certificates.
