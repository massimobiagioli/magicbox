# ADR-0006: Portainer bootstrap credentials and Docker socket access

- **Date:** 2026-10-28
- **Deciders:** MagicBox maintainers

## Status

Accepted

## Context

A fresh Portainer instance exposes an unauthenticated "create admin user" page
for a few minutes; on a LAN, anyone reaching it first becomes administrator.
Portainer manages the local Docker engine through `/var/run/docker.sock`.
Access to that socket is equivalent to root on the host: a client can start a
privileged container that mounts `/`.

## Decision

- The admin password is supplied from Ansible Vault
  (`vault_portainer_admin_password`, at least 12 characters, in the git-ignored
  `inventory/group_vars/magicbox/vault.yml`) and passed to Portainer with
  `--admin-password-file`, so no unauthenticated setup window exists.
- The password file lives at `/opt/magicbox/portainer/secrets/admin_password`
  (root, 0600) and is mounted read-only. Portainer only reads it during the
  first initialisation.
- The Docker socket is bind-mounted into Portainer. No other user is added to
  the `docker` group, and the Docker daemon never listens on TCP; the `docker`
  role asserts that no `dockerd` TCP listener exists.
- Plaintext secrets must never be committed; `tools/check_secrets.py` enforces
  this.

## Alternatives

- **Interactive first-login setup:** opens the takeover window; rejected.
- **Portainer Agent or a socket proxy with restricted API:** reduces blast
  radius for some operations but Portainer needs broad API access to be useful;
  revisit if multi-user access is planned.
- **Docker TCP API with TLS client auth:** more attack surface on the LAN;
  rejected.

## Consequences

- Every Portainer administrator is effectively root on MagicBox. Treat
  Portainer accounts like root accounts: strong unique passwords, few admins.
- Changing `vault_portainer_admin_password` later does **not** change the
  existing admin password (Portainer ignores the file after initialisation);
  change it in the UI instead.
- The plaintext password stays on disk, readable by root only. Root already
  controls Portainer, so this does not add privilege, but disk backups must be
  protected.
