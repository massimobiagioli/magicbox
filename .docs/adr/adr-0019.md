# ADR-0019: Open WebUI in the Ollama stack, on its own HTTPS port

- **Date:** 2026-10-30
- **Deciders:** MagicBox maintainers

## Status

Accepted

## Context

Ollama has an API but no UI. Open WebUI is the de facto chat UI for Ollama
(open source, accounts, model management). The owner wants it at
`https://magicbox.local/openwebui`.

Open WebUI cannot be served under a sub-path: its frontend loads `/static`,
`/_app` and `/api` with absolute paths (verified on v0.12.5), and the
maintainers do not plan sub-path support (discussions #3431, #6650; PR #12002
not merged). The gateway routes by path (ADR-0015) and `/` is Portainer.

Open WebUI has no TLS setting, but its entry point passes extra arguments to
uvicorn, which can serve HTTPS directly. Verified on v0.12.5-slim (local
Docker): HTTPS with uvicorn, headless admin from `WEBUI_ADMIN_EMAIL` and
`WEBUI_ADMIN_PASSWORD` (sign-up then disabled, 403), model list and a chat
completion through a real Ollama; about 330 MB of RAM idle.

## Decision

- Open WebUI is the service `open-webui` of the `ollama` stack (deployed by
  `make stacks`), image pinned to the **slim** variant
  (`stacks_openwebui_image`, about 0.9 GB instead of about 4 GB), volume
  `open_webui_data`. It talks to Ollama on the stack network
  (`http://ollama:11434`).
- HTTPS on `stacks_openwebui_port` (8444) with a copy of the MagicBox
  certificate, passed to uvicorn (`--ssl-certfile`, `--ssl-keyfile`); secure
  cookies; CORS limited to its own origin; published to the LAN only
  (DOCKER-USER, ADR-0012).
- Admin `stacks_openwebui_admin_email` (default `admin@magicbox.local`, a
  login name) with `vault_openwebui_admin_password`, created on the first
  start; sign-up disabled. Sessions signed with `vault_openwebui_secret_key`.
- `OFFLINE_MODE` (no update checks or downloads); OpenAI connections off.
- Gateway: `https://magicbox.local/openwebui` is a 301 redirect to the UI on
  its own port (`stacks_kong_port_redirects`, as for RustFS in ADR-0018).

## Alternatives

- **Proxy under `/openwebui/` with response rewriting:** fragile across
  releases (absolute paths in JavaScript bundles, WebSocket); rejected.
- **Separate host name (`chat.magicbox.local`):** multi-label mDNS names are
  unreliable on Windows and Android and need a new certificate; rejected.
- **Plain HTTP port:** login cookies in clear on the LAN; rejected.
- **Full image:** adds local embeddings and ChromaDB for document chat
  (RAG), about 3 GB more; not needed for chat. The slim image defaults to
  pgvector for RAG, which the PostgreSQL stack does not provide.

## Consequences

- The UI is reached on port 8444; `/openwebui` is only a shortcut.
- `make stacks` now needs `vault_openwebui_admin_password` and
  `vault_openwebui_secret_key`.
- Document upload / RAG does not work with the slim image until an embedding
  engine and vector store are configured.
- The admin password is applied only on the first start (empty database):
  change it in the UI and in the vault together.
- After a certificate renewal by `site.yml`, run `make stacks` to refresh the
  copy.
