# ADR-0007: PDF manuals built from Markdown with a pure-Python toolchain

- **Date:** 2026-10-28
- **Deciders:** MagicBox maintainers

## Status

Accepted

## Context

The project must ship real PDFs (`manuals/installation.pdf`,
`manuals/magicbox-playbook.pdf`) built from editable, version-controlled
sources with a reproducible command. LaTeX, Pandoc, WeasyPrint (Pango) and
wkhtmltopdf all need system packages that are not on the maintainer's
workstation and vary between machines.

## Decision

- Sources are Markdown files in `manuals/src/`. `tools/build_manuals.py`
  converts them with `markdown==3.11.2` (HTML) and `fpdf2==2.8.9` (PDF), both
  pinned in the `docs` dependency group and locked in `uv.lock`.
- The build is deterministic: the PDF creation date comes from
  `SOURCE_DATE_EPOCH` or a fixed default, so unchanged sources produce
  byte-identical PDFs. `make manuals-check` fails when committed PDFs are stale.
- Generated PDFs are committed next to their sources.
- Text is limited to Latin-1 (core PDF fonts); common typographic characters
  are substituted and anything else fails the build with file and line.

## Alternatives

- **Pandoc + LaTeX:** best typography; heavy system dependency; rejected.
- **WeasyPrint:** good CSS support; needs Pango from the OS; rejected.
- **Browser "print to PDF":** not reproducible; rejected.

## Consequences

- `make setup && make manuals` works on any machine with `uv`.
- Layout is simple (no table of contents, no images, no syntax highlighting).
- Non-Latin-1 characters (for example emoji) cannot be used in manuals.
